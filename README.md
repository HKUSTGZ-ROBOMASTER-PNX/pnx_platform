# PnX Platform

这是一个独立于 VS Code 的本机工作台。桌面版使用 Electron 提供窗口和系统文件夹选择框，本地后端只绑定 `127.0.0.1` 的随机端口。实时图表不依赖 VS Code Live Watch 树刷新。程序只读取用户打开的 PnX 工程配置与构建产物，不修改主程序源码。Rust 探针与采样后端随平台源码维护和打包，无需相邻源码仓库。

## Windows 桌面版

下载 Release 中的 `PnX-Platform-Setup-windows-x64.exe`，运行后选择安装目录即可；备用 ZIP 可直接解压使用。安装后的 `PnX-Platform.exe` 需要同目录的 Electron 运行文件，不能单独复制。顶部标签和左侧活动栏可切换“编辑器”“实时曲线”“设置与构建”；齿轮入口直接显示 PnX 图形配置，配置页的“设备工具”按钮可进入探针、串口诊断等工具，再返回图形配置。编辑器页可展开文件树，读取和编辑不超过 2 MiB 的 UTF-8 文本文件，按 Ctrl+S 保存；保存前会检查磁盘文件是否已被其他程序修改。点击“打开文件夹”可选择任意源码目录。普通 CMake 工程可使用其已有的 Configure preset 进行配置和编译；PnX 工程额外提供板卡配置、调试和烧录。

实时曲线页以曲线为主体，左侧显示已添加变量及同排实时值。点击“搜索添加变量”打开弹窗，可按名称筛选、整组勾选或批量添加；变量可指定到不同曲线；“添加曲线”可建立多个面板，通过拖动标题或左右按钮调整顺序，并切换单列、双列或三列布局。每张图的纵向绘图区由 11 条等距水平线分成 10 等份，刻度间隔随数据范围调整，可小于 0.01；紧凑布局下仍绘制全部网格线，只隔行显示文字以避免重叠。内置 Rust 后端每次最多接受 256 路数值变量；选择更多变量时工作台自动分组轮换采集，保留每路独立时间戳，实际单路刷新率会随组数下降。大型 ELF 的变量目录按全局对象逐层展开，结构体或实例可整组勾选到最底层可采集变量；可在搜索弹窗中定位并添加变量。轮换采集时左侧变量值提示距上次采样的时间；每个 Plot 每页绘制最多 64 路，可通过标题栏翻页查看全部所属变量，图例可横向滚动，以免大量曲线同时重绘占满 CPU。所有 Plot 使用同一采样时间轴，旧数据不会因为翻页而显示成刚更新的曲线。图表只在新样本到达且页面可见时绘制，最高 30 FPS；状态栏显示最近约 3 秒的主机实际到达速率。

变量栏右边缘可拖动调整宽度；已添加变量可单独移除，变量名与当前值显示在同一行。搜索弹窗以 ELF 全局对象为根，结构体与实例可逐层展开到可采集叶子，勾选父节点会选择其全部底层变量，部分选中时显示半选；搜索自动展开匹配路径。目录只保留有直接 RAM 地址的全局标量，不展开指针引用。默认“连接目标板”为只读；选择“可写连接”后，确定类型、有效字宽、非指针且标记可写的叶子显示 ✎ 按钮。写入经过服务器再次校验，并由 DAP 写入后读回确认；未定型符号、指针和指针成员不可写。固件运行时仍可能立即覆盖该值。

点击“采集所选变量”建立订阅后，可点击“开始记录”将后端收到的全部样本连续写入当前打开目录的 `captures/`，停止后得到 CSV，也可点击“导出 CSV”下载该文件。CSV 首列为主机采集时间戳（纳秒），后续列对应开始记录时选中的变量；轮换采集期间未采到的列留空。更改订阅或断开连接会结束当前记录；曲线绘制的抽样与 CSV 写入相互独立。

曲线页顶部可设置横坐标时间长度（0.1～120 秒），并将整个曲线区全屏显示。每张 Plot 都有独立的缩放、暂停/继续、全屏和 PNG 导出按钮；鼠标滚轮以指针位置为中心缩放时间轴，按住绘图区拖动可回看已缓存的历史。暂停只冻结该 Plot 的画面，后台采集和 CSV 记录继续。PNG 导出当前视图，尺寸为 1600×900。内存中的绘图历史有总样本数上限，长时间完整记录请使用 CSV。

编辑器可同时打开多个文件标签，保留各标签未保存的内容，并为 C/C++ 源文件提供轻量语法高亮。编辑器顶部提供配置、编译、调试连接、暂停、继续、单步与烧录按钮。点击行号或按 `F9` 可设置或移除源码断点；断点按工作区保留，连接调试器后下发，空心圆表示尚未连接，橙色圆表示后端未能验证该断点。Rust 后端使用目标硬件断点槽，数量有限；ELF 需要包含 DWARF 行号信息，优化后的源码行可能无法设置断点。编译会先保存所有已打开的修改文件，然后从**当前打开的文件夹**执行 CMake 配置与构建。构建并行数取可用逻辑处理器数，最多 8 路。产物位于该文件夹的 `build/pnx-platform/<preset>-<路径哈希>/`；路径哈希让工程移动后使用新构建目录，旧 `build/<preset>/CMakeCache.txt` 不会影响编译，也不会被清理。PnX 调试连接和烧录使用此目录中的 ELF，会先保存并编译，再连接对应权限的 DAP 会话。烧录在编译和连接前要求确认，并在目标板配置启用 motor_demo 时要求额外确认。打开普通 CMake 工程时，PnX 专用的调试和烧录按钮禁用。

编辑器中按 `F12` 或 `Ctrl+点击` 可查找光标处 C/C++ 符号的工程内定义；多个候选位置会显示选择列表，`Alt+←` 返回，`Ctrl+G` 跳转到指定行。查找会读取当前已打开且未保存的文件内容，但目前使用轻量源码扫描，不解析编译选项、宏展开、模板实例化或重载语义；复杂 C++ 工程的精确跳转后续需接入语言服务器。

PnX Platform 支持 ST-Link 和 DAPLink / CMSIS-DAP 探针。进入“设备工具”的“探针与烧录”，点击“扫描探针”，选中设备后即可使用编辑器的“调试连接”，或在曲线页连接目标板；所选 selector 同样用于烧录连接。可手动输入 selector，`auto` 适合只连接一只探针的情况。切换探针时，平台会等待旧适配器进程完全退出；若旧 DAPLink 已拔掉且只剩一只 ST-Link，只读采样会自动改用 ST-Link。调试和烧录要求明确选择新探针；多只探针同时在线时也必须明确选择。DAPLink 需要暴露 CMSIS-DAP 接口并支持目标板的 SWD 连接；不同固件的采样速度和烧录能力可能不同。当前平台支持源码断点、暂停、继续和单步；命中断点会更新暂停状态，暂不自动跳转到当前 PC 行。

首次使用可在“设置与构建 → 设备工具 → 配置与构建”点击“一键检测并配置”。工作台先检查当前 PATH，再扫描常见安装目录；也可在“可选扫描目录”填写工具所在文件夹，此目录优先于 PATH。PnX 固件构建需要 CMake 3.22 或更新版本、Ninja 和完整的 `arm-none-eabi` GCC 工具组。全部找到后，工作台会检查程序版本、保存可执行文件目录并立即用于本次及以后启动的编译；Windows 上还会把 PATH 中缺少的目录追加到当前用户的 PATH，不修改机器级 PATH。其他已打开的终端可能需要重新启动才能读取新 PATH。macOS/Linux 目前仅保存平台内配置，不改 shell 启动文件。缺少工具时会弹出安装提示，可打开 [CMake 官网](https://cmake.org/download/)、[Ninja 官方发布页](https://github.com/ninja-build/ninja/releases) 和 [Arm GNU Toolchain 官网](https://developer.arm.com/tools-and-software/gnu-toolchain#Downloads)；安装程序需用户自行完成，完成后重新检测。

图形配置页集成 PnX 的表单与 Schema：应用参数、Robot 电机增删改、硬件概览、资源绑定、自定义字段和默认值恢复。修改会保存至项目原有 JSON，并检查磁盘版本；本地提示不能替代 CMake 最终校验。工作台内置当前 Schema、默认值、板卡资源描述与表单脚本；打开工程后读取 `configs/boards/<board>/params.json`、`robot.json`，以及可选的 `boards/<board>/board.json`，不运行工程中的配置导出脚本。新增板卡资源时需要更新平台内置描述。

仅编辑器页显示可调整高度的底部输出面板。构建、诊断等输出分别进入对应标签；`＋` 可创建独立输出标签，`Ctrl+反引号` 可显示或隐藏面板。当前标签是输出视图，不提供交互式命令行。编辑器使用接近 VS Code Windows 默认的 Segoe UI 与 Consolas 字体组合。

关闭窗口时会先请求后端断开 DAP 会话，再退出进程；断开探针仍不构成电机停机。编译固件仍需要系统安装 CMake、Ninja 与 Arm 工具链；串口诊断脚本仍需要 Python。Windows 打包脚本使用本机缓存的 Electron 38.8.6；发布脚本使用 Windows 自带的 .NET Framework C# 编译器生成单文件安装包：

```powershell
npm run package:win
npm run package:release:win
```

Windows 11 build 26200 上检测到 Electron GPU 子进程及沙箱化渲染进程启动失败。本程序仅在该构建上关闭 GPU 沙箱和本地工作台窗口的渲染进程沙箱；`contextIsolation`、禁用页面 Node.js，以及仅允许导航到本机工作台地址仍保持启用。其他系统继续使用渲染进程沙箱。当前主机已验证 Electron 窗口及页面加载。备用的 WinForms/WebView2 打包命令是 `npm run package:webview:win`。

## macOS / Linux 打包

Electron 主进程、文件夹选择和后端启动共用同一套源码。在对应系统上安装 Node.js 22.12+、执行 `npm install`，然后运行：

```bash
npm run package:electron:host
```

脚本先使用本仓库 `native/` 中的 Rust workspace 编译 `pnx-dap`，再生成 `dist/PnX Platform-<platform>-<arch>` 并打包后端。对应系统需要安装 Rust、Node.js 和平台编译依赖；macOS/Linux 打包与硬件连接尚未在本机验证。

## Node.js 启动

要求 Node.js、CMake、Ninja 和 PnX 所用的 Arm 工具链已安装。模拟采样还需要先在本仓库执行 `cargo build --release --locked --manifest-path native/Cargo.toml -p pnx-dap`，或运行打包脚本自动构建。

```powershell
cd <pnx_platform 源码目录>
npm start
```

在浏览器打开终端打印的本地 URL。程序只绑定 `127.0.0.1`，使用每次启动随机生成的会话令牌。

## 当前已接入

- 读取 PnX 原有的板级资源快照，选择 H723/F407 的 preset。
- 编辑 `params.json`、`robot.json`，或从界面修改已有电机的型号、CAN 总线和 CAN ID。保存时检查文件是否已被外部修改；配置正确性仍由 PnX 的 CMake Configure 判断。
- 调用原有 CMake Configure/Build；不自动切换 `pnx_bsp` 分支。
- 通过平台内置 Rust DAP 适配器连接模拟或真实探针，按变量 ID 订阅其二进制采样通道。浏览器以最高 30 FPS 绘图并显示最新值。请求采样率不保证实际采样率；界面显示最近一段时间实际到达速率和丢帧数。
- 连接真实探针后可显式烧录当前 preset 的 ELF。连接后若 preset、配置或 ELF 发生变化，必须重新连接才允许烧录。
- 调用已有 USART 请求/响应脚本；该功能需要串口适配器及匹配的板端诊断。

CAN 诊断变量可通过搜索 `can_diag` 加入实时显示。变量列表依赖与板上固件相匹配、带 DWARF 信息的 ELF。

## 边界

当前版本只完成已有能力的集成与高频显示。**没有电机辨识、运动命令或急停能力。** 断开探针不构成电机停机。Rust 后端的采样时间戳来自主机采集链，不能直接用作严格同步的电机辨识数据。ST-Link 只读采集已在当前板卡验证；烧录、调试控制及串口诊断尚需针对目标固件验证。

## 验证

`npm test` 检查文件夹打开、文件读写与目录越界拦截，并使用内置 Rust 模拟适配器检查板级资源加载、DAP 会话、变量订阅和连续采样。不会烧录或驱动硬件。

打包后可运行 `node scripts/electron-ui-smoke.mjs <PnX-Platform.exe 路径>` 验证多文件标签、C/C++ 高亮、未保存文件的编译前保存、Plot 翻页与鼠标拖动，以及模拟目标的实时曲线。设置 `PNX_UI_MOCK_BANKED=1` 可把模拟目标的 4 路变量强制分为两组，检查轮换绘图与采样间隔提示。设置 `PNX_UI_STLINK=1` 后，该脚本改用 ST-Link 只读采集 300 路 RAM 变量，不执行调试控制或烧录。脚本在 `.cache` 保存编辑器与曲线页面截图，并报告渲染主线程任务时间。

连接 ST-Link 时可运行只读压力测试（不烧录、不发送电机命令）：

```powershell
node scripts/stlink-stress.mjs 15 57
$env:PNX_STRESS_PROFILE='direct'; node scripts/stlink-stress.mjs 15 57
$env:PNX_STRESS_PROFILE='ram'; node scripts/stlink-stress.mjs 15 256
$env:PNX_STRESS_PROFILE='ram'; node scripts/stlink-stress.mjs 15 300
```

默认组合参考先前 57 路分组；若当前 ELF 缺少 AHRS 类指针实例，会以 8 路 ThreadX 指针替代。`direct` 组合使用 57 路直接地址变量。`ram` 组合从 ELF 目录中取前 N 路 RAM 地址变量，适合测试 128/256 路吞吐及超过 256 路的轮换采集。当前 ST-Link 以 1000 S/s 请求 300 路 RAM 变量，在 12 秒测试中全部 300 路获得有效值，主机总体到达约 466 S/s，丢帧为 0；具体速率随板卡和变量地址变化。脚本报告收到的通道数、有效数值通道数、主机到达速率、底层丢帧数和适配器状态；没有收到完整通道样本时返回失败。指针根为空或目标固件未初始化时，对应变量可能收到 `null`，界面显示为 `—`。目录中也可能包含目标板无法读取的符号地址；一条错误地址可使整组采样失败，适配器状态会报告读取错误。
